    Code Generation

    Go's go generate toolchain automates repetitive code creation, from string enumerations to protocol buffer bindings. This guide covers the built-in go generate command, popular generators like stringer and mockgen, protobuf compilation, and how to write your own template-based generators.

    What You Will Learn

    • Using the go generate directive and command
    • Generating string methods with stringer
    • Creating mocks with mockgen
    • Compiling protocol buffers with protoc-gen-go
    • Implementing interface compliance checks
    • Building custom template-based generators
    • Using go:linkname for low-level symbol linking

    Prerequisites

    • Go 1.20 or later installed
    • Understanding of interfaces and struct tags
    • Basic familiarity with command-line tools

    The go generate Command

    The go generate tool runs commands embedded in source code comments.

    package shapes

//go:generate stringer -type=Shape
type Shape int

const (
    Circle Shape = iota
    Rectangle
    Triangle
    Pentagon
)
    • go:generate: A special comment that go generate parses and executes
    • stringer: A tool that generates String() methods for named types
    • -type=Shape: Specifies which type to generate string methods for
    $ go generate ./...
$ ls shapes/
shape.go  shape_string.go

    Running go generate

    Execute the command to process all go:generate directives.

    package main

//go:generate echo "Generating code for $GOFILE"
//go:generate go run tools/gen_version.go
//go:generate gofmt -w .

func main() {
    println("Hello, World!")
}

    $ go generate ./...
Generating code for main.go
Version: 1.0.0 (built 2026-09-03)
    • $GOFILE: Environment variable containing the current file name
    • $GOPACKAGE: Environment variable containing the current package name
    • Multiple directives: Each go:generate line runs in order
    • gofmt -w: Formats generated code in-place

    Stringer: Generating String Methods

    The stringer tool creates String() methods that return human-readable names for enum constants.

    //go:build generate

package main

//go:generate stringer -type=Color -output=color_string.go -trimprefix=Color
type Color int

const (
    ColorRed   Color = iota
    ColorGreen
    ColorBlue
    ColorYellow
    ColorPurple
)

func main() {
    c := ColorRed
    println(c.String())
}

    // Code generated by "stringer -type=Color"; DO NOT EDIT.

package main

import "strconv"

func _() {
    var x [1]struct{}
    _ = x[ColorRed-0]
    _ = x[ColorGreen-1]
    _ = x[ColorBlue-2]
    _ = x[ColorYellow-3]
    _ = x[ColorPurple-4]
}

const _Color_name = "RedGreenBlueYellowPurple"

var _Color_index = [...]uint8{0, 3, 8, 12, 18, 24}

func (i Color) String() string {
    if i < 0 || i >= Color(len(_Color_index)-1) {
        return "Color(" + strconv.FormatInt(int64(i), 10) + ")"
    }
    return _Color_name[_Color_index[i]:_Color_index[i+1]]
}

    $ go run .
Red
    • -output: Specifies the output file name
    • -trimprefix: Removes "Color" prefix from generated names
    • Bounds checking: Generated code handles out-of-range values gracefully
    • Compile-time safety: The blank identifier assignment ensures all constants are defined

    Mock Generation with mockgen

    mockgen creates mock implementations of interfaces for testing.

    //go:build generate

package repository

//go:generate mockgen -destination=mock_user_repository.go -package=repository . UserRepository
type UserRepository interface {
    GetByID(id string) (*User, error)
    GetByEmail(email string) (*User, error)
    Create(user *User) error
    Update(user *User) error
    Delete(id string) error
    List(offset, limit int) ([]*User, error)
}

type User struct {
    ID    string
    Name  string
    Email string
}

    package repository

import (
    "testing"

    "github.com/golang/mock/gomock"
)

func TestUserService_GetUser(t *testing.T) {
    ctrl := gomock.NewController(t)
    defer ctrl.Finish()

    mockRepo := NewMockUserRepository(ctrl)

    mockRepo.EXPECT().
        GetByID("user-123").
        Return(&User{
            ID:    "user-123",
            Name:  "Alice",
            Email: "alice@example.com",
        }, nil)

    user, err := mockRepo.GetByID("user-123")
    if err != nil {
        t.Fatalf("unexpected error: %v", err)
    }

    if user.Name != "Alice" {
        t.Errorf("expected name 'Alice', got '%s'", user.Name)
    }
}
    • -destination: Specifies where to write the generated mock file
    • -package: Sets the package name for the generated mock
    • gomock.Controller: Manages mock lifecycle and expectations
    • EXPECT(): Returns an object for setting up method expectations
    • Return(): Specifies the return values when the mock method is called

    Protocol Buffers with protoc-gen-go

    Protocol Buffers provide efficient serialization with strongly-typed messages.

    // user.proto
syntax = "proto3";

package user;

option go_package = "./pb/user;userpb";

message GetUserRequest {
    string user_id = 1;
}

message GetUserResponse {
    string user_id = 1;
    string name = 2;
    string email = 3;
    int64 created_at = 4;
}

service UserService {
    rpc GetUser(GetUserRequest) returns (GetUserResponse);
    rpc ListUsers(ListUsersRequest) returns (ListUsersResponse);
}

message ListUsersRequest {
    int32 page_size = 1;
    string page_token = 2;
}

message ListUsersResponse {
    repeated GetUserResponse users = 1;
    string next_page_token = 2;
}

    $ protoc --go_out=. --go_opt=paths=source_relative \
    --go-grpc_out=. --go-grpc_opt=paths=source_relative \
    user.proto
    • syntax = "proto3": Uses Protocol Buffers version 3 syntax
    • go_package: Specifies the Go import path for generated code
    • protoc: The Protocol Buffers compiler
    • --go_out: Generates Go structs from proto messages
    • --go-grpc_out: Generates gRPC service interfaces and stubs

    Interface Compliance Checks

    Verify at compile time that a type implements an interface.

    package main

import "fmt"

type Writer interface {
    Write(data []byte) (int, error)
}

type FileWriter struct {
    Filename string
}

func (fw *FileWriter) Write(data []byte) (int, error) {
    fmt.Printf("Writing %d bytes to %s\n", len(data), fw.Filename)
    return len(data), nil
}

var _ Writer = (*FileWriter)(nil)

type NetworkWriter struct {
    Address string
}

func (nw *NetworkWriter) Write(data []byte) (int, error) {
    fmt.Printf("Sending %d bytes to %s\n", len(data), nw.Address)
    return len(data), nil
}

var _ Writer = (*NetworkWriter)(nil)

func main() {
    writers := []Writer{
        &FileWriter{Filename: "output.txt"},
        &NetworkWriter{Address: "10.0.0.1:8080"},
    }

    for _, w := range writers {
        w.Write([]byte("hello"))
    }
}
    • var _ Writer = (*FileWriter)(nil): Compile-time assertion that FileWriter implements Writer
    • The blank identifier: Discards the value, only the type check matters
    • Nil pointer: The assertion doesn't need an actual instance
    $ go build .
Writing 5 bytes to output.txt
Sending 5 bytes to 10.0.0.1:8080

    Template-Based Code Generation

    Build custom generators using Go's text/template package.

    //go:build generate

package main

import (
    "os"
    "text/template"
)

var tmpl = template.Must(template.New("").Parse(`// Code generated by gen_methods.go; DO NOT EDIT.

package {{.Package}}

type {{.Type}}Methods struct{}

{{range .Methods}}
func ({{$.Type}}Methods) {{.Name}}(input string) (string, error) {
    return input + "_{{.Suffix}}", nil
}
{{end}}
`))

type Method struct {
    Name   string
    Suffix string
}

func main() {
    data := struct {
        Package string
        Type    string
        Methods []Method
    }{
        Package: "generated",
        Type:    "User",
        Methods: []Method{
            {"Validate", "validated"},
            {"Sanitize", "sanitized"},
            {"Normalize", "normalized"},
        },
    }

    f, err := os.Create("user_methods.go")
    if err != nil {
        panic(err)
    }
    defer f.Close()

    tmpl.Execute(f, data)
}

    // Code generated by gen_methods.go; DO NOT EDIT.

package generated

type UserMethods struct{}

func (UserMethods) Validate(input string) (string, error) {
    return input + "_validated", nil
}

func (UserMethods) Sanitize(input string) (string, error) {
    return input + "_sanitized", nil
}

func (UserMethods) Normalize(input string) (string, error) {
    return input + "_normalized", nil
}
    • template.Must: Panics on parse errors for early detection
    • {{.Field}}: Template syntax for accessing struct fields
    • {{range}}: Iterates over slices in the template
    • DO NOT EDIT: Standard marker for generated files

    go:linkname for Symbol Linking

    go:linkname allows access to unexported symbols across packages.

    go:linkname

    go:linkname bypasses Go's encapsulation guarantees. Use only when absolutely necessary and document the dependency clearly.

    package main

import (
    "fmt"
)

//go:linkname runtimeNano runtime.nanotime
func runtimeNano() int64

type privateStruct struct {
    secret string
    count  int
}

//go:linkname privateField main.privateStruct.secret
var privateField string

func main() {
    nano := runtimeNano()
    fmt.Printf("Runtime nanoseconds: %d\n", nano)

    s := privateStruct{secret: "hidden", count: 42}
    fmt.Printf("Private field via linkname: %s\n", privateField)
    fmt.Printf("Struct: %+v\n", s)
}
    • //go:linkname: Directives that map symbols across package boundaries
    • runtime.nanotime: Access to the runtime's internal nanosecond timer
    • Private fields: Can access unexported struct fields
    • Use with extreme caution: This breaks encapsulation and may break with Go version updates
    $ go run .
Runtime nanoseconds: 1725359730123456789
Private field via linkname: hidden
Struct: {secret:hidden count:42}

    go:embed for Embedded Files

    Embed files directly into the binary at compile time.

    package main

import (
    "embed"
    "fmt"
    "html/template"
)

//go:embed templates/*
var templateFS embed.FS

//go:embed static/*
var staticFS embed.FS

//go:embed config/default.yaml
var defaultConfig []byte

type PageData struct {
    Title   string
    Content string
}

func main() {
    tmpl, err := template.ParseFS(templateFS, "templates/*.html")
    if err != nil {
        panic(err)
    }

    data := PageData{
        Title:   "Embedded Template",
        Content: "This is embedded content!",
    }

    tmpl.Execute(os.Stdout, data)

    fmt.Printf("\nDefault config: %s\n", string(defaultConfig))
}
    • //go:embed: Embeds files matching the pattern into the binary
    • embed.FS: A read-only file system containing embedded files
    • []byte: For small files, embed directly as a byte slice
    • Template embedding: Parse templates from the embedded filesystem

    Best Practices

    Practice Recommendation
    Mark generated files Always include DO NOT EDIT header
    Use go:generate Keep generation commands in source near the types they generate
    Version control generated code Commit generated files for reproducible builds
    Document dependencies List required tools in README
    Avoid go:linkname Prefer interfaces or exported APIs
    Test generated code Ensure generated code passes tests

    Troubleshooting

    Problem Solution
    Generator not found Install with go install <tool>@latest
    Wrong output directory Check -output flag and go_package option
    Circular linkname Avoid linking symbols that depend on each other
    Template parse error Use template.Must to catch errors early
    Embedded file not found Verify the file exists relative to the source file

    • go generate runs commands embedded in source code comments
    • stringer generates String() methods for enum types
    • mockgen creates mock implementations for interface testing
    • protoc compiles Protocol Buffers into Go structs and gRPC stubs
    • Compile-time interface checks prevent runtime surprises
    • Template-based generators automate repetitive code patterns
